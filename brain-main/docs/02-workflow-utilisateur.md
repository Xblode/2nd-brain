# 02 — Workflow utilisateur

1. **Capture.** L'utilisateur dépose une note dans l'Inbox. Rien n'y est ajouté automatiquement.
2. **Triage.** Sur demande, l'assistant propose une destination : doublon, question, idée, fait, décision, exigence, tâche ou référence.
3. **Cadrage.** Objectif, utilisateurs, contraintes, critères de réussite, dépendances, risques, questions ouvertes. Pas de plan d'implémentation détaillé avant ce cadrage.
4. **Planification.** Lots cohérents : résultat, périmètre, critères, vérifications.
5. **Exécution.** L'utilisateur choisit le lot. Le moins d'agents possible, en parallèle seulement si les tâches sont indépendantes.
6. **Revue.** Écarts et risques visibles.
7. **Continuité.** Mettre à jour `STATE.md` et les documents existants via une proposition. Pas de compte-rendu séparé si le document canonique suffit.

Les documents optionnels (`ROADMAP`, `BUGS`, etc.) se créent à la demande.
