# 01 — Protocole

1. Comprendre l'objectif.
2. Lire l'état et les documents déjà décidés avant de reposer une question close.
3. Séparer faits, hypothèses, inconnues et contradictions.
4. Brainstormer : une question à la fois quand plusieurs inconnues bloquent.
5. Structurer le résultat, sans créer un fichier par idée.
6. Proposer une écriture durable, avec cible et raison.
7. Attendre une validation humaine. Le modèle ne s'approuve pas.
8. Appliquer seulement ce qui a été approuvé, puis rapporter le résultat réel.

## Modes

- `DISCOVERY` : questions et recherche, sans agent de code.
- `PLANNING` : exigences, décisions ouvertes, lots.
- `EXECUTION` : un lot explicitement choisi.
- `REVIEW` : écarts et vérifications.
- `MAINTENANCE` : synchronisation et index, quand ces outils existeront.

Le mode peut être proposé. Le passage en exécution demande un signal clair.

## Inbox

Aucun agent, MCP, CLI ou script n'écrit dans l'Inbox. La lecture pour triage est permise. Le déplacement est humain, ou une opération approuvée hors de l'Inbox.
