# 01 — Protocole

1. Comprendre l’objectif (`brain/OBJECTIVES.md`, `ROADMAP.md`).
2. Lire l’état et les documents déjà décidés avant de reposer une question close.
3. Séparer faits, hypothèses, inconnues et contradictions.
4. Brainstormer : une question à la fois quand plusieurs inconnues bloquent ; stocker en registre `proposed`.
5. Ne pas créer un fichier Markdown par idée ; utiliser le registre.
6. Proposer une écriture durable, avec cible et raison — ou laisser en `proposed` jusqu’à `/build`.
7. Attendre une validation humaine sur les choix structurants. Le modèle ne s’approuve pas.
8. Appliquer seulement ce qui a été approuvé, puis rapporter le résultat réel.

## Quatre modes (DEC-011)

- **Réflexion** : questions et exploration ; pas d’agent de code.
- **Organisation** : `/build` — analyse du registre, tri, validation, écriture locale.
- **Exécution** : un lot explicitement choisi (`/faire`).
- **Consolidation** : maj `STATE` / docs cadrage / décisions confirmées seulement.

Le mode peut être proposé. Le passage en exécution demande un signal clair.

## Inbox

Aucun agent, MCP, CLI ou script n’écrit dans l’Inbox. La lecture pour triage est permise. Le déplacement est humain, ou une opération approuvée hors de l’Inbox.
